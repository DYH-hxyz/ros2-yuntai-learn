## 1. 先说结论

机械臂和差速底盘的控制目标完全不同：

- 差速底盘的核心目标是“让轮子按某个速度转起来”。
- 机械臂关节的核心目标是“让关节运动到某个角度”。

因此，机械臂不能继续沿用底盘的这一套：

```text
velocity command -> WriteSpec -> WheelMode -> 轮子恒速转动
```

机械臂现在使用这一套：

```text
position command -> WritePosEx -> PositionMode -> 运动到目标角度
```

当前最终配置是：

```text
arm_joint1: position command + position state
arm_joint2: position command + position state
```

控制器使用：

```yaml
arm_joints_controller:
  ros__parameters:
    joints: ["arm_joint1", "arm_joint2"]
    interface_name: "position"
```

代码中的 `read()` 和 `write()` 也已经对应修改为：

```text
read():  舵机 PRESENT_POSITION -> 弧度 -> position state
write(): position command 弧度 -> STS 原始位置 -> WritePosEx
```

## 2. 原来的问题是什么

### 2.1 机械臂 URDF 声明的是位置接口

机械臂原本的 `arm.ros2_control.xacro` 已经声明了：

```xml
<joint name="arm_joint1">
    <command_interface name="position"/>
    <state_interface name="position"/>
</joint>

<joint name="arm_joint2">
    <command_interface name="position"/>
    <state_interface name="position"/>
</joint>
```

也就是说，从 ros2_control 的角度看，机械臂控制器会提供：

```text
arm_joint1/position
arm_joint2/position
```

但是原来的硬件接口实现是从底盘复制过来的，思想仍然是速度控制：

- 校验 `velocity` 命令接口。
- 校验 `position + velocity` 状态接口。
- 准备调用轮子速度模式。
- `read()` 原本应该读速度，再通过速度积分位置。
- `write()` 原本应该取速度命令，再调用 `WriteSpec()`。

这会造成接口契约不一致：

```text
URDF / controller: position
HardwareInterface: velocity
```

控制器和硬件接口拿的不是同一组接口，控制器自然无法正常申请命令接口。

### 2.2 原来的源文件还调用了不存在的位置函数

原始机械臂源文件里已经出现了：

```cpp
driver_->activateWithPositionMode(joint1_motor_id_);
```

但旧版 `FeetechDriver` 只有速度相关方法：

```cpp
activateWithVelocityMode()
getVelocityRadianPerSec()
setTargetVelocityRadianPerSec()
```

并没有真正实现：

```cpp
activateWithPositionMode()
getPositionRadian()
setTargetPositionRadian()
```

所以这不是只修改 `read()` 和 `write()` 两个函数就够了，驱动层和 SDK 层也必须补齐位置控制能力。

### 2.3 原来的 URDF 还使用了模拟硬件

原来的机械臂硬件块大致是：

```xml
<hardware>
    <plugin>mock_components/GenericSystem</plugin>
    <param name="calculate_dynamics">true</param>
</hardware>
```

这只能让 ros2_control 使用模拟系统，不能打开串口，也不会访问真实的飞特舵机。

因此必须切换为：

```xml
<hardware>
    <plugin>my_robot_hardware/ArmHardwareInterface</plugin>
    <param name="port">/dev/ttyACM0</param>
    <param name="joint1_motor_id">1</param>
    <param name="joint2_motor_id">2</param>
</hardware>
```

## 3. 改造前后的核心对比

### 3.1 总体对比

| 对比项 | 改造前的底盘式思路 | 改造后的机械臂位置思路 |
|---|---|---|
| 控制对象 | 差速底盘左右轮 | 机械臂两个旋转关节 |
| 控制目标 | 轮子角速度 | 关节目标角度 |
| 控制器 | `diff_drive_controller` | `forward_command_controller` |
| 命令接口 | `velocity` | `position` |
| 状态接口 | `position` + `velocity` | `position` |
| 舵机模式 | WheelMode，轮子模式 | PositionMode，角度模式 |
| SDK 写函数 | `WriteSpec()` | `WritePosEx()` |
| SDK 读函数 | `ReadSpeed()` | `ReadPos()` |
| ros2_control 单位 | `rad/s` | `rad` |
| 位置来源 | 速度积分 | 直接读取舵机位置寄存器 |
| 停机方式 | 速度写 0 | 目标位置改为当前位置 |
| 关节命名 | `base_left_wheel_joint` | `arm_joint1`、`arm_joint2` |

### 3.2 命令接口对比

#### 改造前

底盘控制器最终给硬件接口的是轮速：

```cpp
double left_cmd = get_command("base_left_wheel_joint/velocity");
double right_cmd = get_command("base_right_wheel_joint/velocity");

driver_->setTargetVelocityRadianPerSec(left_motor_id_, left_cmd);
driver_->setTargetVelocityRadianPerSec(right_motor_id_, right_cmd);
```

这里的命令值含义是：

```text
每秒转多少弧度
```

例如：

```text
1.0 rad/s = 轮子以每秒 1 弧度的速度旋转
```

#### 改造后

机械臂控制器给硬件接口的是关节角度：

```cpp
const double joint1_command = get_command("arm_joint1/position");
const double joint2_command = get_command("arm_joint2/position");

driver_->setTargetPositionRadian(joint1_motor_id_, joint1_command);
driver_->setTargetPositionRadian(joint2_motor_id_, joint2_command);
```

这里的命令值含义是：

```text
关节最终应该到达多少弧度
```

例如：

```text
1.5708 rad ≈ 90 度
```

### 3.3 状态读取对比

#### 改造前

底盘读取舵机速度：

```cpp
double left_vel = driver_->getVelocityRadianPerSec(left_motor_id_);
double right_vel = driver_->getVelocityRadianPerSec(right_motor_id_);
```

然后用：

```cpp
new_position = old_position + velocity * period
```

得到软件积分位置。

#### 改造后

机械臂直接读取舵机当前位置：

```cpp
const double joint1_position = driver_->getPositionRadian(joint1_motor_id_);
const double joint2_position = driver_->getPositionRadian(joint2_motor_id_);

set_state("arm_joint1/position", joint1_position);
set_state("arm_joint2/position", joint2_position);
```

这意味着机械臂位置状态不是估算值，而是来自舵机的 `PRESENT_POSITION` 寄存器。

### 3.4 舵机模式对比

#### 轮子速度模式

```text
MODE = 1
WheelMode()
WriteSpec()
```

舵机会持续按照速度运行。速度为正或负通常代表不同转向。

#### 关节位置模式

```text
MODE = 0
PositionMode()
WritePosEx()
```

舵机会按照目标位置运行，并在目标角度附近停止。

## 4. 完整的数据流

机械臂的位置控制链如下：

```text
                         ROS 2 进程边界
┌──────────────────────────────────────────────────────────────┐
│ forward_command_controller                                  │
│                                                              │
│ 用户发布 position 命令                                       │
│        │                                                     │
│        ▼                                                     │
│ arm_joint1/position                                          │
│ arm_joint2/position                                          │
└────────┬─────────────────────────────────────────────────────┘
         │ ros2_control 进程内命令接口
         ▼
┌──────────────────────────────────────────────────────────────┐
│ ArmHardwareInterface                                        │
│                                                              │
│ write()                                                      │
│ get_command("arm_joint1/position")                          │
│ get_command("arm_joint2/position")                          │
└────────┬─────────────────────────────────────────────────────┘
         │ C++ 函数调用
         ▼
┌──────────────────────────────────────────────────────────────┐
│ FeetechDriver                                                │
│                                                              │
│ 弧度 -> 0~4095 原始位置                                      │
│ setTargetPositionRadian()                                   │
└────────┬─────────────────────────────────────────────────────┘
         │ C++ SDK 调用
         ▼
┌──────────────────────────────────────────────────────────────┐
│ scs::sms_sts                                                 │
│                                                              │
│ WritePosEx(id, position, speed, acceleration, error)         │
└────────┬─────────────────────────────────────────────────────┘
         │ 串口协议
         ▼
┌──────────────────────────────────────────────────────────────┐
│ Feetech STS 舵机                                             │
│                                                              │
│ 角度模式运行到目标位置                                       │
└──────────────────────────────────────────────────────────────┘
```

反馈方向相反：

```text
舵机 PRESENT_POSITION
        │
        ▼
ReadPos()
        │
        ▼
FeetechDriver::getPositionRadian()
        │
        ▼
ArmHardwareInterface::read()
        │
        ▼
arm_joint1/position、arm_joint2/position
        │
        ▼
joint_state_broadcaster / RViz / 控制器
```

这里要注意：

- `controller` 不直接调用 `WritePosEx()`。
- `controller` 不认识串口和舵机 ID。
- `FeetechDriver` 不认识 `arm_joint1` 这个 ROS 关节名。
- `ArmHardwareInterface` 是二者之间的翻译层。

## 5. 控制器为什么必须改成位置接口

当前控制器配置是：

```yaml
arm_joints_controller:
  ros__parameters:
    joints: ["arm_joint1", "arm_joint2"]
    interface_name: "position"
```

这表示控制器会申请：

```text
arm_joint1/position
arm_joint2/position
```

控制器发布的命令消息通常是一个与关节顺序对应的数组：

```text
[arm_joint1_target_position, arm_joint2_target_position]
```

例如：

```text
[0.0, 1.5708]
```

可以理解为：

```text
关节 1 到 0 度
关节 2 到 90 度
```

这个控制器不会生成速度控制命令，因此硬件接口必须读取：

```cpp
get_command("arm_joint1/position")
get_command("arm_joint2/position")
```

如果硬件接口错误地读取：

```cpp
get_command("arm_joint1/velocity")
```

那么有两个问题：

1. URDF 中根本没有声明 `arm_joint1/velocity`。
2. 控制器也不会向这个不存在的接口写值。

所以控制器配置、URDF 接口声明、硬件接口 `get_command()` 三者必须完全一致。

## 6. URDF ros2_control 声明对比

### 6.1 改造前

```xml
<ros2_control name="Arm" type="system">
    <hardware>
        <plugin>mock_components/GenericSystem</plugin>
        <param name="calculate_dynamics">true</param>
    </hardware>

    <joint name="arm_joint1">
        <command_interface name="position"/>
        <state_interface name="position"/>
    </joint>

    <joint name="arm_joint2">
        <command_interface name="position"/>
        <state_interface name="position"/>
    </joint>
</ros2_control>
```

接口名字虽然已经是位置接口，但硬件仍然是模拟硬件。

### 6.2 改造后

```xml
<ros2_control name="Arm" type="system">
    <hardware>
        <plugin>my_robot_hardware/ArmHardwareInterface</plugin>
        <param name="port">/dev/ttyACM0</param>
        <param name="joint1_motor_id">1</param>
        <param name="joint2_motor_id">2</param>
    </hardware>

    <joint name="arm_joint1">
        <command_interface name="position"/>
        <state_interface name="position"/>
    </joint>

    <joint name="arm_joint2">
        <command_interface name="position"/>
        <state_interface name="position"/>
    </joint>
</ros2_control>
```

改造后发生了三件事：

1. `mock_components/GenericSystem` 换成真实插件。
2. 增加串口参数 `port`。
3. 增加两个舵机 ID 参数。

### 6.3 参数如何进入 C++

URDF 中的参数会进入：

```cpp
params.hardware_info.hardware_parameters
```

代码通过键名读取：

```cpp
port_ = get_param("port", "/dev/ttyACM0");
joint1_motor_id_ = std::stoi(get_param("joint1_motor_id", "1"));
joint2_motor_id_ = std::stoi(get_param("joint2_motor_id", "2"));
```

因此以下名称必须一模一样：

```text
URDF:  joint1_motor_id
C++:   get_param("joint1_motor_id", "1")
```

不能写成：

```text
joint_1_motor_id
left_motor_id
motor1_id
```

除非 C++ 代码也同步修改。

## 7. ArmHardwareInterface 逐函数说明

文件：

```text
src/my_robot_hardware/src/arm_hardware_interface.cpp
```

### 7.1 `on_init()`：解析接口和硬件参数

第一步必须调用基类：

```cpp
hardware_interface::SystemInterface::on_init(params)
```

这是 Jazzy 新版 API 的关键步骤。基类会根据 URDF 建立内部接口存储。如果漏掉这一步，后面即使调用 `set_state()` 和 `get_command()`，ros2_control 也可能没有真正导出接口。

之后检查机械臂关节数量：

```cpp
if (info.joints.size() != 2)
```

当前实现明确要求两个关节：

```text
arm_joint1
arm_joint2
```

然后逐个检查：

```cpp
command interface: position
state interface: position
```

检查逻辑等价于：

```text
每个关节必须有 position command
每个关节必须有 position state
```

最后读取：

```text
port
joint1_motor_id
joint2_motor_id
```

这里只创建 `FeetechDriver`，不立即打开串口：

```cpp
driver_ = std::make_shared<my_robot_hardware::FeetechDriver>(port_);
```

### 7.2 `on_configure()`：配置阶段

当前实现返回成功：

```cpp
return hardware_interface::CallbackReturn::SUCCESS;
```

没有把串口打开动作放在这里，原因是：

- `on_init()` 负责解析配置。
- `on_configure()` 负责进入 configured 状态。
- `on_activate()` 才代表控制器准备真正使用硬件。

这样硬件生命周期更清晰。

### 7.3 `on_activate()`：打开串口并切换位置模式

激活过程有两步：

#### 第一步：清零 ROS 状态接口

```cpp
for (const auto & joint : info_.joints)
{
    for (const auto & state_interface : joint.state_interfaces)
    {
        const std::string interface_name =
            joint.name + "/" + state_interface.name;
        set_state(interface_name, 0.0);
    }
}
```

这只是初始化 ros2_control 内部状态，随后每个周期的 `read()` 会用真实舵机位置覆盖它。

#### 第二步：打开串口并切位置模式

```cpp
if (!driver_->init())
{
    return hardware_interface::CallbackReturn::ERROR;
}

driver_->activateWithPositionMode(joint1_motor_id_);
driver_->activateWithPositionMode(joint2_motor_id_);
```

`activateWithPositionMode()` 内部做的事情是：

```text
1. 写 MODE=0，进入角度定位模式
2. ReadPos() 读取当前角度
3. 把当前角度写成目标角度
```

这样切模式时不会突然追逐舵机里残留的旧目标位置。

### 7.4 `on_deactivate()`：位置模式下安全停止

速度模式可以通过“速度写 0”停车，但位置模式不是这样。

如果只把速度写 0，位置模式下并没有明确意义。因此当前实现使用：

```cpp
driver_->deactivatePosition(joint1_motor_id_);
driver_->deactivatePosition(joint2_motor_id_);
```

内部逻辑是：

```text
1. 读取当前位置
2. 把当前位置重新写成目标位置
```

这样舵机不会继续追逐最后一个位置命令。

### 7.5 `read()`：读取真实位置状态

当前实现：

```cpp
const double joint1_position =
    driver_->getPositionRadian(joint1_motor_id_);
const double joint2_position =
    driver_->getPositionRadian(joint2_motor_id_);

set_state("arm_joint1/position", joint1_position);
set_state("arm_joint2/position", joint2_position);
```

完整的含义是：

```text
ReadPos(id=1) -> 原始位置 -> 弧度 -> arm_joint1/position
ReadPos(id=2) -> 原始位置 -> 弧度 -> arm_joint2/position
```

这里不再使用：

```cpp
position += velocity * period.seconds();
```

原因是 STS 舵机已经能直接提供当前位置，直接读取比软件积分更适合机械臂位置反馈。

### 7.6 `write()`：发送目标位置

当前实现：

```cpp
const double joint1_command = get_command("arm_joint1/position");
const double joint2_command = get_command("arm_joint2/position");

driver_->setTargetPositionRadian(joint1_motor_id_, joint1_command);
driver_->setTargetPositionRadian(joint2_motor_id_, joint2_command);
```

数据方向是：

```text
controller command
    -> get_command()
    -> 弧度值
    -> FeetechDriver
    -> 原始位置值
    -> WritePosEx()
    -> 舵机
```

## 8. FeetechDriver 逐个位置 API 说明

文件：

```text
src/my_robot_hardware/include/my_robot_hardware/feetech_driver.hpp
```

### 8.1 `activateWithPositionMode()`

```cpp
void activateWithPositionMode(int motor_id)
```

功能：

```text
把舵机设置为角度模式，并保持当前角度。
```

底层步骤：

```cpp
packet_handler_->PositionMode(motor_id, error);
setTargetPositionRadian(motor_id, getPositionRadian(motor_id));
```

### 8.2 `getPositionRadian()`

```cpp
double getPositionRadian(int motor_id)
```

底层调用：

```cpp
packet_handler_->ReadPos(motor_id, present_position_raw, error);
```

返回值转换为弧度：

```cpp
return static_cast<double>(present_position_raw)
       * kRawPositionToRadian;
```

它把厂商协议细节藏在驱动层，因此 `ArmHardwareInterface` 不需要知道：

- PRESENT_POSITION 在哪个寄存器。
- 位置值占几个字节。
- 是否需要小端拼接。
- 如何解析符号位。

这些都由 SDK 处理。

### 8.3 `setTargetPositionRadian()`

```cpp
void setTargetPositionRadian(int motor_id, double target_position_rad)
```

输入是 ROS 侧的弧度，内部换算为舵机原始位置：

```cpp
const int position_raw = static_cast<int>(std::lround(
    positive_position / kTwoPi * kPositionTicksPerRevolution));
```

然后调用：

```cpp
packet_handler_->WritePosEx(
    motor_id,
    position_raw,
    kPositionSpeed,
    kAcceleration,
    error);
```

`WritePosEx()` 的参数意义：

| 参数 | 含义 |
|---|---|
| `motor_id` | 舵机 ID |
| `position_raw` | 目标位置原始值 |
| `kPositionSpeed` | 到目标位置的速度限制 |
| `kAcceleration` | 加速度档位 |
| `error` | 舵机返回的错误码 |

### 8.4 `deactivatePosition()`

```cpp
void deactivatePosition(int motor_id)
```

它不是把速度设置为 0，而是：

```cpp
setTargetPositionRadian(motor_id, getPositionRadian(motor_id));
```

这符合位置模式的语义：目标位置等于当前位置，停止继续运动。

## 9. SDK 新增 PositionMode

文件：

```text
src/my_robot_hardware/ftservo_sdk/scservo_sdk/sms_sts.h
src/my_robot_hardware/ftservo_sdk/scservo_sdk/sms_sts.cpp
```

SDK 原本有：

```cpp
int WheelMode(int scs_id, int& error);
```

它执行：

```cpp
write1ByteTxRx(scs_id, SMS_STS_MODE, 1, error);
```

这代表：

```text
MODE = 1 -> 轮子模式
```

机械臂需要新增：

```cpp
int PositionMode(int scs_id, int& error);
```

实现为：

```cpp
int sms_sts::PositionMode(int scs_id, int& error)
{
    return write1ByteTxRx(scs_id, SMS_STS_MODE, 0, error);
}
```

这代表：

```text
MODE = 0 -> 角度定位模式
```

这样 `FeetechDriver` 不需要直接操作寄存器地址，仍然通过 SDK 提供的高层接口完成模式切换。

## 10. 位置单位换算

### 10.1 STS 位置单位

当前 SDK 按以下约定处理位置：

```text
0~4095 个原始位置单位对应一整圈 0~2π
```

因此：

```text
每个原始位置单位 = 2π / 4096 rad
```

代码中的常量是：

```cpp
static constexpr int kPositionTicksPerRevolution = 4096;
static constexpr double kTwoPi = 2.0 * M_PI;
static constexpr double kRawPositionToRadian =
    kTwoPi / kPositionTicksPerRevolution;
```

### 10.2 读取方向

舵机原始位置转 ROS 弧度：

```text
position_rad = position_raw × 2π / 4096
```

例如：

| 原始位置 | 约等于弧度 | 约等于角度 |
|---:|---:|---:|
| 0 | 0 | 0° |
| 1024 | 1.5708 | 90° |
| 2048 | 3.1416 | 180° |
| 3072 | 4.7124 | 270° |
| 4095 | 6.2817 | 接近 360° |

### 10.3 写入方向

ROS 弧度转舵机原始位置：

```text
position_raw = round(position_rad / 2π × 4096)
```

代码会先把目标角度归一化到 `[0, 2π)`：

```cpp
const double normalized_position =
    std::fmod(target_position_rad, kTwoPi);
```

负角度会加上 `2π`，避免直接写入负的原始位置值。

### 10.4 关于机械臂关节零点

当前代码假设：

```text
舵机原始位置 0 对应 ROS 关节角度 0
```

如果机械安装时舵机的物理零点不是这个位置，还需要加入零点偏移：

```text
ros_angle = (raw_position - zero_offset) × 2π / 4096
```

这次改造没有擅自加入零点偏移参数，因为当前项目还没有提供每个关节的标定值。实际安装后如果发现：

- RViz 显示的初始角度不对。
- 发送 0 弧度后机械臂没有到预期物理零位。
- 发送正角度时方向与模型相反。

就需要进一步增加：

```text
joint1_zero_offset
joint2_zero_offset
joint1_direction
joint2_direction
```

这些属于机械标定，不应该和基础的串口位置读写混在一起猜测。

## 11. CMake 和 pluginlib 为什么必须同步改

### 11.1 CMake 加入机械臂源文件

原来的动态库只编译：

```cmake
add_library(my_robot_hardware SHARED
  src/mobile_base_hardware_interface.cpp
)
```

这样即使 `arm_hardware_interface.cpp` 存在，也不会进入最终的 `.so`。

现在改为：

```cmake
add_library(my_robot_hardware SHARED
  src/mobile_base_hardware_interface.cpp
  src/arm_hardware_interface.cpp
)
```

这保证机械臂类的实现会被编译进：

```text
libmy_robot_hardware.so
```

### 11.2 pluginlib XML 注册机械臂类

文件：

```text
src/my_robot_hardware/my_robot_hardware.xml
```

新增：

```xml
<class name="my_robot_hardware/ArmHardwareInterface"
       type="arm_hardware::ArmHardwareInterface"
       base_class_type="hardware_interface::SystemInterface">
```

三个名称要分别理解：

| XML 字段 | 实际含义 |
|---|---|
| `name` | URDF `<plugin>` 中写的插件名字 |
| `type` | C++ 类的完整名字 |
| `base_class_type` | 继承的 ros2_control 基类 |

URDF 中写的是：

```xml
<plugin>my_robot_hardware/ArmHardwareInterface</plugin>
```

它必须与 XML 的 `name` 完全相同。

XML 中的 `type`：

```xml
type="arm_hardware::ArmHardwareInterface"
```

必须与 C++ 命名空间和类名完全一致。

### 11.3 C++ 注册宏

源文件末尾还必须有：

```cpp
PLUGINLIB_EXPORT_CLASS(
  arm_hardware::ArmHardwareInterface,
  hardware_interface::SystemInterface)
```

这三处必须形成闭环：

```text
URDF plugin name
    == XML class name

XML type
    == C++ namespace + class

PLUGINLIB_EXPORT_CLASS
    == C++ namespace + class + base class
```

缺少任意一处，都可能出现：

```text
Failed to create instance
class not registered
```

## 14. 真实硬件测试注意事项

### 14.1 先确认串口设备

```bash
ls /dev/ttyACM* /dev/ttyUSB*
```

如果设备不是 `/dev/ttyACM0`，就要修改：

```xml
<param name="port">实际设备路径</param>
```

### 14.2 确认舵机 ID

当前配置是：

```text
joint1_motor_id = 1
joint2_motor_id = 2
```

如果实际 ID 不同，必须修改 URDF 参数，不能只修改控制器 YAML。

### 14.3 确认波特率

driver 当前使用：

```cpp
kBaudrate = 1000000
```

舵机总线的实际波特率必须与它一致，否则会出现：

```text
ReadPos 超时
WritePosEx 通信失败
RX_CORRUPT
```

### 14.4 先小角度测试

不要一开始就发送很大的角度命令。建议顺序：

```text
1. 读取当前位置
2. 发送接近当前位置的小目标
3. 确认两个关节方向
4. 确认模型与实体角度一致
5. 再逐渐扩大运动范围
```

### 14.5 注意机械限位

URDF 中当前限制是：

```xml
<limit lower="0" upper="${pi/2}" ... />
```

这表示模型允许的关节范围是：

```text
0 到 π/2
```

但底层 `FeetechDriver` 当前只负责原始位置转换，没有在 driver 层强制限制到这个范围。因此真实舵机测试时必须确保命令不超过机械结构的安全范围。

### 14.6 方向可能需要单独处理

如果某个舵机安装方向与 URDF 轴方向相反，可能需要：

```text
ros_angle = -motor_angle
```

或者：

```text
target_motor_angle = -target_ros_angle
```

这属于安装方向标定，不是 `position` 接口是否正确的问题。

## 15. 常见问题排查

| 现象 | 可能原因 | 检查方式 |
|---|---|---|
| `missing state/command interfaces` | URDF 接口与 C++ 校验不一致 | 确认每个关节都有 `position` command/state |
| 控制器找不到 position 接口 | 控制器名称或接口名称不一致 | 检查 `interface_name: position` |
| `Failed to create instance` | plugin XML、C++ 类名或注册宏不一致 | 检查三处 `ArmHardwareInterface` 名称 |
| 插件类找不到 | CMake 没有编译 arm 源文件 | 检查 `add_library()` 是否包含 `arm_hardware_interface.cpp` |
| 串口打开失败 | 设备路径错误或权限不足 | 检查 `/dev/ttyACM*` 和 `dialout` |
| ReadPos 超时 | ID、波特率、接线或供电错误 | 单独用 SDK ping 测试舵机 |
| 舵机不动但控制器 active | 命令未发布或 ID 错误 | 查看 command 话题和驱动日志 |
| 舵机突然跳到奇怪角度 | 切模式前残留目标或零点不一致 | 检查 `PositionMode()` 和机械零点 |
| RViz 角度显示不对 | 零点偏移或方向未标定 | 增加零点/方向标定参数 |
| 两个关节动作互相不对 | 关节与舵机 ID 映射错误 | 检查 `joint1_motor_id`、`joint2_motor_id` |
| C++ 编辑器提示找不到 `scservo_def.h` | VS Code IntelliSense includePath 未同步 | CMake 能编译则不是源码错误，补 SDK includePath 即可 |

## 16. 最终文件职责总结

### `arm_hardware_interface.hpp`

只声明机械臂硬件接口类：

```text
继承 SystemInterface
声明 on_init/on_configure/on_activate/on_deactivate/read/write
保存 driver、串口、两个舵机 ID
```

### `arm_hardware_interface.cpp`

连接 ros2_control 和 FeetechDriver：

```text
校验 URDF 接口
读取硬件参数
管理生命周期
read() 读取位置状态
write() 下发位置命令
注册 pluginlib 类
```

### `feetech_driver.hpp`

连接抽象接口和厂商 SDK：

```text
管理串口 SDK 对象
切换 PositionMode
读取 ReadPos
弧度与原始位置互换
调用 WritePosEx
处理位置模式停机
```

### `sms_sts.h/.cpp`

提供 Feetech STS 的协议级高层 API：

```text
定义位置寄存器
实现 ReadPos
实现 WritePosEx
实现 PositionMode
```

### `arm.ros2_control.xacro`

声明 ROS 侧硬件契约：

```text
加载哪个插件
有哪些关节
有哪些 command/state interface
串口是什么
舵机 ID 是什么
```

### `my_robot_controllers.yaml`

声明控制器如何使用这些接口：

```text
arm_joint1 + arm_joint2
interface_name = position
```

### `CMakeLists.txt`

保证源代码真的进入动态库：

```text
编译 arm_hardware_interface.cpp
链接 SDK
生成 libmy_robot_hardware.so
```

### `my_robot_hardware.xml`

让 pluginlib 能通过名字找到 C++ 类：

```text
my_robot_hardware/ArmHardwareInterface
    -> arm_hardware::ArmHardwareInterface
```

## 最终一句话总结

这次改造的本质不是简单地把几个 `velocity` 字符串替换成 `position`，而是完整打通了四层契约：

```text
控制器 position
    -> ros2_control position command
    -> ArmHardwareInterface::write()
    -> FeetechDriver 弧度转换
    -> SDK WritePosEx()
    -> STS 位置模式舵机
```

反馈链路则是：

```text
STS PRESENT_POSITION
    -> SDK ReadPos()
    -> FeetechDriver 弧度转换
    -> ArmHardwareInterface::read()
    -> ros2_control position state
    -> joint_state_broadcaster / RViz / 控制器
```

只有这两条链路同时对齐，机械臂的位置控制才是完整的。
